# Telegram-боты с памятью

Три Telegram-бота на Python (aiogram 3.x) с интеграцией OpenAI-совместимого API (ProxyAPI).

## Боты

### 1. Короткая память (`bot_short_memory.py`)
Бот запоминает последние 10 сообщений каждого пользователя для контекстного диалога.

### 2. Длинная память (`bot_long_memory.py`)
Бот позволяет загружать файлы (PDF, TXT, DOCX), извлекает текст, разбивает на чанки,
создаёт эмбеддинги и сохраняет в векторную базу ChromaDB. При вопросе бот ищет
релевантные фрагменты и отвечает на основе загруженных документов (RAG).

### 3. Комбинированная память (`bot_dual_memory.py`)
Объединяет оба подхода: бот помнит последние 10 сообщений диалога (короткая память)
и может отвечать на вопросы по загруженным документам (долгая память).
При ответе бот ищет контекст в векторной базе и добавляет историю диалога.

## Требования

- Python 3.12+
- Токен Telegram-бота (получить у [@BotFather](https://t.me/BotFather))
- API-ключ ProxyAPI

## Установка

1. Клонируйте репозиторий:
   ```bash
   git clone <repository-url>
   cd vpf06-telegram-memory-bot
   ```

2. Создайте виртуальное окружение и активируйте его:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate          # Windows
   source .venv/bin/activate       # Linux/macOS
   ```

3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

4. Настройте переменные окружения:
   ```bash
   copy .env.example .env          # Windows
   cp .env.example .env            # Linux/macOS
   ```

   Откройте `.env` и заполните:
   ```
   BOT_TOKEN=ваш_токен_от_BotFather
   OPENAI_API_KEY=ваш_ключ_proxyapi
   OPENAI_BASE_URL=https://api.proxyapi.ru/openai/v1
   OPENAI_MODEL=gpt-5.6-luna
   TEMPERATURE=1
   LOG_LEVEL=INFO
   ```

## Как работает бот с длинной памятью (RAG)

1. **Загрузка файла:** пользователь загружает PDF, TXT или DOCX
2. **Извлечение текста:** бот парсит файл и извлекает текст
3. **Чанкирование:** текст разбивается на фрагменты по ~500 символов
4. **Эмбеддинги:** каждый фрагмент векторизуется через OpenAI Embeddings
5. **Сохранение:** векторы сохраняются в ChromaDB (persistent storage)
6. **Вопрос:** пользователь задаёт вопрос
7. **Поиск:** ChromaDB находит релевантные фрагменты
8. **Ответ:** модель отвечает строго на основе найденных фрагментов

## Как работает бот с комбинированной памятью

Бот объединяет два типа памяти:

### Короткая память
- Последние 10 сообщений диалога для каждого пользователя
- Хранится в оперативной памяти (deque)
- Обеспечивает контекст разговора

### Длинная память
- Загруженные файлы (PDF, TXT, DOCX) сохраняются в ChromaDB
- Текст разбивается на чанки (~500 символов)
- Каждый чанк векторизуется через OpenAI Embeddings
- При вопросе бот ищет релевантные фрагменты

### Логика ответа
1. Сообщение пользователя сохраняется в короткую память
2. Бот ищет релевантные фрагменты в ChromaDB (долгая память)
3. Формируется запрос: `системный промпт + история + контекст документов + сообщение`
4. Если контекст не найден — ответ на основе истории и общих знаний
5. Ответ отправляется пользователю и сохраняется в историю

## Тестирование

Бот с длинной памятью протестирован на файле `company.txt`.

### Тестовые вопросы

**Факты о компании:**
- Как называется ваша компания?
- Чем вы занимаетесь?
- Когда вы начали работу?

**Услуги:**
- Какие услуги вы предоставляете?
- Разрабатываете ли вы Telegram-ботов?
- Занимаетесь ли вы автоматизацией?

**Контакты:**
- Как с вами связаться?
- Какой у вас телефон?
- Где находится ваш офис?
- Когда вы работаете?

**FAQ:**
- Работаете ли вы с ИП и самозанятыми?
- Какие технологии вы используете?
- Сколько времени занимает разработка бота?
- Даёте ли вы гарантию на свои работы?

**Отзывы клиентов:**
- Что пишут о вас клиенты?
- Есть ли у вас отзывы?

**Проверка на галлюцинации (информации в документе нет):**
- Какие у вас цены на услуги?
- Сколько у вас сотрудников?

### Результаты тестирования

| Что проверяем | Результат |
|---|---|
| Поиск фактов | ✅ На все вопросы из блоков 1–5 бот дал точные ответы из документа |
| Отсутствие галлюцинаций | ✅ На вопросы из блока 6 бот ответил: «Информация не найдена в документе» |
| Поиск по нескольким фрагментам | ✅ Вопрос «Какие услуги вы предоставляете?» собрал информацию из разных частей текста |
| Точность цитирования | ✅ Ответы совпадают с текстом документа |

### Сценарий тестирования гибридного бота (bot_dual_memory.py)

#### 1. Проверка долгой памяти (работа с документом)

1. Загрузить файл `company.txt` (или любой другой) в бота.
2. Задать вопросы по документу:
   - «Как называется компания?»
   - «Какие услуги вы предоставляете?»
   - «Где находится офис?»

**Ожидаемый результат:** Бот отвечает на вопросы на основе загруженного файла.

#### 2. Проверка короткой памяти (история диалога)

1. Задать вопрос: «Какой был мой первый вопрос?»

**Ожидаемый результат:** Бот должен вспомнить и назвать первый вопрос пользователя.

2. Задать ещё один вопрос: «Как я могу связаться с вами?»
3. Сразу после этого спросить: «Что я только что спросила?»

**Ожидаемый результат:** Бот должен правильно назвать «Как я могу связаться с вами?».

#### 3. Проверка связки двух типов памяти

1. Спросить в одном сообщении: «Как называется компания и какой у неё телефон?»

**Ожидаемый результат:** Бот должен найти оба факта в документе и дать полный ответ.

2. Задать вопрос с отсылкой к истории: «Ты сказал, что компания называется "ТехноКод". А какие у них услуги?»

**Ожидаемый результат:** Бот должен вспомнить название из истории диалога и найти услуги в документе.

#### 4. Проверка реакции на отсутствие информации

1. Спросить про информацию, которой нет в документе: «Сколько у вас сотрудников?» (если этой информации нет в файле)

**Ожидаемый результат:** Бот должен ответить, что не знает, и не придумывать ответ.

2. Сделать это после вопросов по документу: «А теперь скажи, какая у тебя модель?» (это про ИИ, а не про документ)

**Ожидаемый результат:** Бот может использовать общие знания, но не путать их с данными из файла.

#### 5. Проверка работы команды /clear

1. Задать вопрос по документу → получить ответ.
2. Ввести команду `/clear`.
3. Снова спросить: «Как меня зовут?» (если имя было в диалоге до очистки)

**Ожидаемый результат:** Бот должен забыть историю диалога и ответить, что не знает имени.

### Результаты тестирования гибридного бота

| Что проверяется | Ожидание |
|---|---|
| Долгая память | Точные ответы на фактические вопросы из документа |
| Короткая память | Помнит историю (вопросы, имя пользователя, контекст) |
| Связка памяти | Совмещает факты из документа и историю диалога |
| Отсутствие галлюцинаций | Не выдумывает отсутствующие факты |
| Команда /clear | Короткая память очищается, но долгая остаётся |

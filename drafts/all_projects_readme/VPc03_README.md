# База данных спортивного клуба (Sports Club DB)

SQLite база данных для управления спортивным клубом.

## Таблицы и их назначение

| Таблица | Назначение |
|---------|------------|
| `members` | Участники клуба (ФИО, контакты, дата регистрации, статус) |
| `trainers` | Тренеры (ФИО, специализация, зарплата, дата приёма) |
| `subscription_types` | Типы абонементов (название, цена, длительность, лимит посещений) |
| `subscriptions` | Активные абонементы участников (связь member + subscription_type) |
| `classes` | Занятия (тренер, тип, дата/время, вместимость, аудитория) |
| `visits` | Посещения занятий (связь member + class, статус посещения) |
| `payments` | Платежи участников (сумма, дата, способ оплаты) |

## Ограничения и проверки

### NOT NULL
Все критические поля имеют ограничение `NOT NULL`:
- Имя, фамилия, email, телефон у участников и тренеров
- Дата регистрации, специализация, зарплата
- Тип абонемента, цена, длительность
- Связи между таблицами (member_id, trainer_id, class_id)

### UNIQUE
Уникальные значения для:
- `members.email` — email участника не может повторяться
- `trainers.email` — email тренера не может повторяться
- `subscription_types.name` — название типа абонемента уникально

### CHECK
Проверки целостности данных:
1. `members` — возраст участника не менее 14 лет
2. `subscription_types` — цена > 0, длительность > 0, лимит посещений > 0
3. `classes` — максимальное количество участников > 0, длительность > 0
4. `visits` — статус посещения в допустимых значениях (attended/cancelled/no_show)
5. `payments` — сумма платежа > 0

### Индексы (ускорители поиска)
| Индекс | Поле | Назначение |
|--------|------|------------|
| `idx_members_email` | members.email | Быстрый поиск по email |
| `idx_classes_trainer_id` | classes.trainer_id | Поиск занятий тренера |
| `idx_visits_member_id` | visits.member_id | Поиск посещений участника |
| `idx_payments_member_id` | payments.member_id | История платежей участника |
| `idx_subscriptions_status` | subscriptions.status | Поиск активных абонементов |
| `idx_classes_timestamp` | classes.class_timestamp | Поиск по дате занятий |

## Что показывают проверочные запросы

1. **Активные абоненты** — список участников с действующими абонементами
2. **Запись на занятия по датам** — количество участников на каждом занятии (с двумя форматами даты)
3. **Тренеры и их классы** — полное расписание по каждому тренеру
4. **Неактивные участники** — те, кто не посещал клуб более 3 дней
5. **Топ-3 популярных занятия** — занятия с наибольшей посещаемостью
6. **Выручка по типам абонементов** — сколько заработал клуб по каждому типу
7. **Конфликты расписания** — пересечения занятий у одного участника
8. **Статистика по типам занятий** — популярность каждого вида активности
9. **Общая статистика клуба** — сводные показатели
10. **Топ-5 активных участников** — самые частые посетители

## Пошаговая инструкция по запуску

### Шаг 1: Создать директорию и перейти в неё
```powershell
mkdir C:\SQLite_DB
cd C:\SQLite_DB
```

### Шаг 2: Создать базу данных и выполнить схему
```powershell
sqlite3 sports.db < schema.sql
```

### Шаг 3: Заполнить базу тестовыми данными
```powershell
sqlite3 sports.db < seed.sql
```

### Шаг 4: Запустить проверочные запросы
```powershell
sqlite3 sports.db < checks.sql
```

Или открыть базу в SQLite Browser и выполнять запросы вручную из файла `checks.sql`.

## Форматы хранения дат

В базе используются два формата для дат:

| Формат | Пример | Тип | Назначение |
|--------|--------|-----|------------|
| Текстовый | `27.10.2024, 09:00:00` | TEXT | Читаемый формат для отчётов |
| Timestamp | `1730006400` | INTEGER | Unix timestamp для вычислений |

## Требования

- Python 3.x (для скриптов create_db.py и run_checks.py)
- PowerShell (для Windows) или любой терминал
- SQLite 3.x (встроен в Python)

## Альтернативный запуск через Python (если нет sqlite3 CLI)

```powershell
# Создать базу данных
cd C:\SQLite_DB
python create_db.py

# Запустить проверочные запросы
python run_checks.py
```

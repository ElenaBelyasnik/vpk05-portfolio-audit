# Recipe Project — дизайнерский генератор рецептов в Word

Скрипт на Python, который превращает **любой рецепт из txt- или docx-файла** в красиво оформленный документ `.docx`: одна страница A4, шрифт Georgia, декоративная рамка страницы и фото блюда в левом верхнем углу с обтеканием текстом.

- **Стиль оформления** выбирается автоматически или задаётся директивой в исходнике (цвет словом или hex, тема, готовый стиль — см. ниже).
- **Размер шрифта подбирается динамически** под объём рецепта: скрипт оценивает, сколько строк займёт текст, и берёт максимально крупный шрифт (основной текст до ~13 пт), при котором рецепт гарантированно умещается на одном листе A4. Длинные рецепты автоматически набираются мельче, но не ниже нижнего предела, чтобы не мельчить.
- **Источник-ссылка кликабельный**: URL внизу документа — настоящая гиперссылка (Ctrl+Click в Word), окрашенная в акцентный цвет активного стиля.

## Виртуальное окружение

Зависимость у проекта одна — `python-docx`, поэтому скрипт запускается и из глобального Python. Но изолированное окружение ставит библиотеку локально в папку проекта, не трогает системный Python и гарантирует одинаковые версии на любой машине. Делается это один раз перед первым запуском.

### 1. Создать окружение

Все команды — из папки `recipe_project/`.

```bash
# Windows (PowerShell или cmd)
python -m venv venv

# Linux / macOS
python3 -m venv venv
```

Внутри `venv/` окажется свой интерпретатор и свой `pip`.

### 2. Активировать

| ОС / оболочка | Команда активации |
|---|---|
| Windows, PowerShell | `.\venv\Scripts\Activate.ps1` |
| Windows, cmd | `.\venv\Scripts\activate.bat` |
| Linux / macOS (bash, zsh) | `source venv/bin/activate` |

Признаки успешной активации: в начале приглашения появилось `(venv)`, а `python --version` показывает версию из окружения (на Windows — `where python`, на Linux/macOS — `which python` первой строкой отдаёт путь внутри `venv/`).

> Если PowerShell пишет «выполнение скриптов отключено политикой выполнения»:
> `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` — разрешение действует только до закрытия текущего окна.

### 3. Установить зависимость

Пока окружение активно, обычный `pip` уже принадлежит ему:

```bash
pip install python-docx
```

### 4. Запустить

```bash
python generate_recipe.py
```

Что должно лежать в `source/` и где оказывается готовый файл — в разделе «Как это работает» ниже.

### Выход из окружения

```bash
deactivate
```

### Если активировать окружение не нужно

Можно обратиться к интерпретатору напрямую — активация для этого не требуется, а пути в скрипте считаются от расположения самого файла:

```powershell
.\venv\Scripts\python.exe generate_recipe.py
```

```bash
venv/bin/python generate_recipe.py    # Linux / macOS
```

> Папку `venv/` вместе с проектом не переносят — внутри зашиты абсолютные пути и версия Python той машины, где окружение создали. На новой машине её просто удаляют и создают заново с шага 1.

## Как это работает

1. Положите рецепт в виде txt- или docx-файла в папку `source/` (текст из docx извлекается автоматически: абзацы и таблицы).
2. Рядом (в ту же папку) можно положить картинку блюда — она попадёт в левый верхний угол документа после заголовка. Картинка подхватывается автоматически, если её имя совпадает с именем файла рецепта (например, `Медовый рулет.txt` + `Медовый рулет.jpg`); если в папке ровно одна картинка — используется она.
3. Активируйте виртуальное окружение (если оно есть) и запустите скрипт:

   ```bash
   python generate_recipe.py
   ```

   Как создать и активировать окружение — см. раздел «Виртуальное окружение» выше.

4. Готовый `.docx` появится в папке **«Загрузки»** пользователя (`%USERPROFILE%\Downloads`) с тем же именем, что и исходный файл.

Скрипт обрабатывает **все** txt- и docx-файлы из `source/` за один запуск. Для каждого файла в консоль печатается выбранный стиль, его источник и масштаб шрифта, например:

```text
[готово] ...Баклажаны.docx (с фото) [стиль: бирюзовый, создан новый (градиент подобран автоматически); масштаб шрифта: 1.4]
```

## Формат входного файла

```text
🍰Название рецепта, короткое описание        ← первая строка: название до запятой/точки
Любой описательный текст                    ← попадёт в подзаголовок
Ингредиенты:                                ← начало списка ингредиентов
Мука ... 225 г                              ← строки с "..." или " - " = ингредиенты
2 ст.л раст.масло (у меня оливковое)        ← количество в начале строки тоже
                                               распознаётся и разворачивается
                                               в "раст.масло (…) — 2 ст.л"
Крем:                                       ← строка с ":" в конце = подзаголовок группы
Сметана ... 300 г
Выпекать при 180 градусах 15 минут         ← строка без "..." = заметка (курсивом)
👍Пошаговый рецепт:                         ← начало шагов приготовления
Шаг первый.
Шаг второй.
Рецепт взят отсюда https://...              ← строка с URL = источник (кликабельная ссылка внизу справа)
```

Эмодзи из текста автоматически удаляются. Поддерживаются кодировки UTF-8 и Windows-1251 (для txt). Если явных заголовков разделов нет, строки классифицируются эвристически (по шаблону `название ... количество`).

Помимо «Ингредиенты:» распознаётся заголовок «Состав:». Если после шагов приготовления встречается повторный блок «Состав:» (например, второй рецепт в том же тексте), он оформляется как **альтернативный рецепт**: выводится внизу документа отдельно, со своим заголовком, списком ингредиентов и нумерацией шагов с единицы. Короткие строки без цифр внутри списка ингредиентов трактуются как ингредиент без количества («Экстракт ванили»).

## Стили оформления

### Автовыбор по названию рецепта

Если в исходнике нет директив, стиль выбирается по ключевым словам в названии:

| Стиль | Гамма | Ключевые слова (примеры) |
|---|---|---|
| `honey` — медовая (по умолчанию) | тёмно-коричневые заголовки, медовые акценты, кремовый фон, золотая рамка | медовик, мёд, мед |
| `salad` — салатная | тёмно-зелёные заголовки, оливковые акценты, светло-салатовый фон | салат, овощ, баклажан, капуст, оливье… |
| `berry` — ягодная | бордово-розовая гамма | ягод, вишн, клубник, яблоч, лимон… |

Ничего не совпало — применяется `DEFAULT_STYLE` (медовая).

### Директивы стиля в исходнике (для ИИ)

Стиль можно задать прямо в тексте рецепта — в начале или в конце файла. Достаточно одной строки:

```text
Стиль: бирюзовый
```

Что понимает скрипт после «Стиль:» (проверяется по порядку):

1. **Имя существующего стиля** (`салатный`, `honey`…) или совпадение с его ключевыми словами — стиль используется как есть.
2. **Цвет** — русским словом (`красный`, `бирюзовый`, `коричневый`, `лавандовый`…, полный список в `COLOR_HUES`) или hex (`Стиль: #B3541E`). Стиль создаётся динамически: указанный цвет становится акцентом (маркеры, номера, количества), а весь градиент строится вокруг него — тёмный заголовок, светлые фон и плашки, линии в том же тоне.
3. **Знакомая тема** — готовая гармоничная гамма из `THEME_GRADIENTS`: `хлеб…` (ржано-пшеничная), `краб…` (коралловая), `абрикос…`, `шоколад…`, `кофе…`.
4. **Незнакомая тема** — палитра строится детерминированно из имени (цветовой тон вычисляется хешем): одно и то же имя всегда даёт одну и ту же гамму.

Повторный запуск с той же директивой даёт тот же стиль — стили создаются один раз за запуск и детерминированы.

Для полной кастомизации можно дополнительно указать палитру в hex (все поля или частично):

```text
Стиль: Бордовый
Заголовки: #4A2C17         ← палитра: все поля или частично
Акценты: #8B5A2B
Текст: #33281F
Подписи: #8C7B6B
Фон: #F7F1EA               ← фон страницы
Плашки: #EFE2D1            ← фон плашек заголовков разделов
Линии: #9C6B3C             ← линии и рамка страницы
```

Правила применения:

- **Только имя** («Стиль: салатный») — имеющийся стиль или автоградиент для нового.
- **Полная или частичная палитра** — создаётся новый стиль с этим именем; недостающие поля наследуются от подобранного или дефолтного стиля.
- **Явная директива имеет высший приоритет**: если строка «Стиль: …» задана, автоопределение по ключевым словам в названии рецепта полностью игнорируется.
- Строки-директивы автоматически удаляются из рецепта и никуда не попадают. Строка «Стиль: …» может стоять в начале, в конце файла или быть частью короткой строки.

## Оформление результата

- **Одна страница A4** с компактными полями и межстрочными интервалами; размер шрифта подобран под объём рецепта.
- **Шрифт Georgia** для всего документа.
- Палитра выбранного стиля: заголовки, акценты, фон страницы, плашки разделов, двойная рамка по периметру.
- **Фото блюда** — плавающий объект в левом верхнем углу (под заголовком), текст ингредиентов обтекает его.
- Заголовки разделов — плашки с полосой слева и разрядкой букв.
- Ингредиенты — маркерные списки с выделенным количеством; шаги — с акцентной нумерацией.
- **Источник** — кликабельная гиперссылка в акцентном цвете стиля.

## Кастомизация

Основные настройки — в начале `generate_recipe.py`; всё, что касается стилей, — в `recipe_styles.py`:

| Константа       | Где | Назначение                                        |
|-----------------|-----|---------------------------------------------------|
| `FONT`          | `generate_recipe.py` | Шрифт документа (Georgia) |
| `PAGE_CAPACITY` / `MAX_SCALE` / `MIN_SCALE` | `generate_recipe.py` | Параметры динамического подбора шрифта |
| `IMG_WIDTH_CM`  | `generate_recipe.py` | Ширина фото в левом верхнем углу (5,5 см) |
| `OUTPUT_DIR`    | `generate_recipe.py` | Куда сохранять результат (по умолчанию «Загрузки») |
| `STYLES`        | `recipe_styles.py` | Стили оформления: цвета + ключевые слова |
| `DEFAULT_STYLE` | `recipe_styles.py` | Стиль по умолчанию, если ничего не совпало |
| `THEME_GRADIENTS` | `recipe_styles.py` | Тематические гаммы для автоградиента |
| `COLOR_HUES`    | `recipe_styles.py` | Русские названия цветов для директивы «Стиль: <цвет>» |

### Как добавить свой стиль

Допишите **одну запись** в словарь `STYLES` в `recipe_styles.py` — цвета и ключевые слова в названии рецепта, по которым стиль выберется сам:

```python
'chocolate': {
    'keywords': ('шоколад', 'какао', 'брауни', 'тирамису'),
    'colors': {
        'title':  RGBColor(0x4A, 0x2C, 0x17),  # заголовки
        'accent': RGBColor(0x8B, 0x5A, 0x2B),  # акценты, номера шагов
        'text':   RGBColor(0x33, 0x28, 0x1F),  # основной текст
        'muted':  RGBColor(0x8C, 0x7B, 0x6B),  # подписи
        'page':    'F7F1EA',                   # фон страницы (hex)
        'heading': 'EFE2D1',                   # фон плашек разделов
        'border':  '9C6B3C',                   # линии и рамка
    },
},
```

Словарь проверяется сверху вниз, поэтому более специфичные стили (например, «медовая» для медовиков) стоит ставить раньше общих. Стили, для которых ничего не совпало, получают `DEFAULT_STYLE`.

> Вместо ручного добавления в код удобнее писать директивы стиля прямо в исходнике рецепта — см. раздел «Директивы стиля в исходнике». Тематические гаммы автоградиента пополняются так же просто — одной записью в `THEME_GRADIENTS`.

## Примечания

- Если результат не открывается на перезапись (файл открыт в Word), скрипт сохранит документ под именем «имя (2).docx».
- При работе в IDE предупреждения вида `Import "docx" could not be resolved` означают лишь, что интерпретатор IDE не видит установленную библиотеку python-docx; на работу скрипта они не влияют. Укажите IDE интерпретатор из `venv/` (в VS Code: `Ctrl+Shift+P` → `Python: Select Interpreter`).
